# 配置项（CI）管理

> 说明：本文件路径刻意不放在 `cmdb/` 子目录下——mkdocs 的 `exclude_docs` 全局排除了 `cmdb/`
> （见 `mkdocs.yml`），放到该目录会导致帮助站点缺失本页。

## 适用场景

- 维护配置项台账与关系（依赖、部署、归属）；
- 变更/事件影响面分析的基础数据。

## 关键概念

- **类型与属性**：CI 类型定义属性集合（如服务器：IP、机架、负责人）；
- **关系**：上下游依赖（A 依赖 B）是影响面分析的输入；
- **数据质量**：字段缺失/关系悬空会降低影响分析准确度。

## 常用操作

1. **列表**（`/cmdb/cis`）：按类型/负责人筛选；可生成"按类型统计"只读汇总；
2. **新建**（`/cmdb/cis/create`）：选择类型 → 填写必填属性 → 建立与现有 CI 的关系；
3. **详情**（`/cmdb/cis/:id`）：
   - 查看属性、关系图与关联工单；
   - 生成**影响分析计划**（只读）：上下游、关联工单、历史事件。

## 常见问题

- **属性不知道该填什么？** 参考类型定义与"CI 属性该怎么填？"建议卡；
- **关系怎么建？** 在详情页关系面板新增；跨环境关系请注明来源；
- **影响分析为空？** 补齐关系与属性后重试；悬空关系不会进入分析。

## AI 助手可用动作（页面建议卡）

- 「生成影响分析计划」（CI 详情）：只读分析计划 + 证据引用；
- 「它关联了哪些工单？」：列出未关闭关联工单并说明影响；
- 「按类型统计 CI」（列表）：只读统计与最近变更最多的类型。
