# 创建事件

## 适用场景

- 确认服务中断/降级后，第一时间登记事件（先建立协同，再补充细节）；
- 值班交接时补齐影响面与时间线。

## 字段填写要点

| 字段 | 要点 |
|---|---|
| 标题 | 服务 + 现象，例如"订单服务 5xx 比例升高" |
| 级别 | 依据影响范围（用户量/核心链路）初判，可后调 |
| 影响范围 | 受影响系统、地区、客户范围 |
| 时间线 | 首次发现时间、当前状态、已采取的止血动作 |

## 处置建议

1. 先止血（限流/回滚/切换），再定位根因；
2. 影响面不清时，用 AI 生成"影响分析计划"（只读），据此确认关联 CI 与上下游；
3. 与关联工单互链，避免重复处置。

## 常见问题

- **不确定级别？** 参考"级别该怎么定？"建议卡，先按较高处理、后续调整；
- **需要拉哪些人？** 参考值班表与影响的服务负责人（on-call 信息在值班管理页）。

## AI 助手可用动作（页面建议卡）

- 「帮我完善事件描述」：引导补齐影响范围/影响面/时间线，产出可编辑草稿；
- 「级别该怎么定？」：说明级别判断标准并给出当前建议。
