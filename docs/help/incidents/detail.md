# 事件详情

## 适用场景

- 事件处置期间协同与记录；
- 复盘（Postmortem）前梳理影响面与时间线。

## 关键概念

- **影响面分析**：关联 CI 的上下游关系 + 关联工单统计 + 历史事件；
- **处置记录**：每次关键动作写入时间线，便于对外沟通与复盘；
- **只读建议**：AI 只产出分析与计划（plan/analysis），不会自动改状态或级别。

## 常用操作

1. 打开「问 AI」或助手面板，生成**影响分析计划**（只读）；
2. 依据计划核对受影响 CI、上下游依赖与关联工单；
3. 更新状态/级别与处置记录，关闭前确认业务恢复；
4. 复盘：结合历史相似事件对比处置效率。

## 常见问题

- **关联 CI 是空的？** 先在 CMDB 完善该服务的配置项与关系，再重新生成影响面；
- **能自动升级事件吗？** 不会；升级/降级始终由人确认执行；
- **复盘需要哪些证据？** 时间线、影响面、根因假设与验证、改进项。

## AI 助手可用动作（页面建议卡）

- 「影响面分析计划」：产出只读分析计划（含证据引用）；
- 「历史上出现过类似事件吗？」：检索相似事件与当时处置方式。
