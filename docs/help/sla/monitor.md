# SLA 监控

## 适用场景

- 服务台/值班识别临近违约与已违约工单；
- SLA 达标率复盘与改进。

## 关键概念

- **响应/解决目标**：由 SLA 定义（按优先级/服务目录）确定；
- **暂停与恢复**：等待用户等状态可能暂停计时（取决于 SLA 配置）；
- **违约风险**：剩余时间小于阈值（如 20%）即视为风险，需要升级处理。

## 常用操作

1. 查看"临近违约"清单，按剩余时间排序；
2. 对高风险工单：确认分派人是否在线、必要时升级并通知用户；
3. 违约后：填写违约原因（区分内部处理延迟/等待用户/依赖阻塞）；
4. 定期复盘达标率与违约分布。

## 常见问题

- **为什么这张单有违约风险？** 查看关键时间点（创建/首次响应/解决目标）与暂停区间；
- **时间计算方式？** 按 SLA 定义的日历/工作时长计算，暂停区间不计入；
- **能批量改 SLA 吗？** 变更 SLA 定义会影响新工单；存量工单按快照规则处理。

## AI 助手可用动作（页面建议卡）

- 「找出临近违约的工单」：只读扫描 + 优先处理建议；
- 「为什么这张单有违约风险？」：解释关键时间点与风险来源。
