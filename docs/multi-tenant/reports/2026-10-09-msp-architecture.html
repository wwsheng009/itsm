MSP 多租户平台架构 · 一套系统，多个客户，服务商跨客户运营

整体只有一套部署、一个数据库：所有客户共用同一套程序，靠「客户标识」把数据互相隔开； 服务商员工经过身份 + 权限 + 分配三重检查后，可以跨客户处理工单。下图自上而下：谁在用 → 统一入口 → 应用能力 → 安全防线 → 数据底座。

📖 阅读顺序

自上而下共五层：谁在用 → 统一入口 → 应用能力 → 安全防线 → 数据底座。上层是使用场景，下层是支撑与保障；蓝色箭头表示请求自上而下经过的路径。

🎨 颜色与符号

  • 蓝＝客户侧　紫＝服务商侧　青＝平台治理
  • 红＝安全防线　绿＝数据与隔离
  • →箭头＝请求 / 流程方向　①–④＝防线顺序
  • 底部两条链路：跨客户授权（四步）与工单旅程（四步）

📚 关键术语

  • 租户：一家客户（或服务商）独立的数据空间
  • 分配关系：服务商员工与客户的绑定，决定能服务哪些客户
  • 隔离锁：数据库层强制按客户过滤，程序有疏漏也拿不到别家数据
  • fail-closed：识别不到身份或权限就拒绝，不猜测、不兜底
