# 场景 06 · 客户方：建工单类型 → 新建工单

> **状态**：当前（2026-10-05 实测）｜**定位**：客户在自己租户内把业务跑起来（有类型可选的工单）
> **读者**：客户方管理员、测试
> **前置**：[场景 03](./03-tenant-provisioning-first-admin.md) 客户租户已开通；客户方管理员已改密登录

---

## 1. 场景目标与验收判据

| 判据 | 通过标准 |
|---|---|
| 类型可用 | `/tickets/types` 列表出现工单类型（名称/编码/默认优先级） |
| 可选类型 | 新建工单页面能选择该类型（**模板不含类型时这里为空，必须先建**） |
| 可建单 | 提交后生成工单号（`TKT-<年月>-<序号>`），工单列表可查 |
| 客户可见 | 客户方列表/详情可见完整工单（标题/描述/优先级/状态） |

## 2. 第一步：建工单类型（`/tickets/types`）

| 步骤 | 操作 | 预期界面反馈 |
|---|---|---|
| 1 | 客户方管理员登录，进入 **工单类型**（`/tickets/types`） | 页头「工单类型 / 租户级类型、动态表单及流程策略配置」；按钮「从预设安装」「新建类型」；表格列：名称、编码、默认优先级… |
| 2 | 点击 **「新建类型」** | 弹出表单：**编码 \<code\>**、**名称**、描述、分类、默认优先级、排序、图标、颜色；下方为高级区（自定义字段 / 工作流绑定 / SLA / 自动分配） |
| 3 | 填写最小要素：编码=`TS_GENERAL`、名称=`通用支持`、默认优先级=`中` | 校验通过 |
| 4 | 提交 | 弹窗关闭；列表出现 `通用支持（TS_GENERAL）` |

> 快捷路径：点击 **「从预设安装」** 打开「工单类型预设库」，对目标预设点 **「安装」**。注意：`install_preset` 是独立权限点，默认模板角色未必包含；无权限时按钮报错——此时用「新建类型」。
>
> **已知限制**（v1.69 登记）：租户模板 7 项基线**不含**工单类型，因此**新客户租户建单页的类型选择器初始为空**——本步骤是必做前置。

## 3. 第二步：新建工单（`/tickets/create`）

| 步骤 | 操作 | 预期界面反馈 |
|---|---|---|
| 5 | 打开 **新建工单**（`/tickets/create`） | 页头「新建工单」；顶部显示工单类型摘要与 **「选择工单类型」/「更换类型」** |
| 6 | 点击选择类型 → 弹层选中 `通用支持` | 类型徽标回显；若该类型带动态字段，下方出现「<类型名> · 类型专属字段」 |
| 7 | 填写：**标题**（≥2 字，如 `VPN 无法连接`）；**详细描述**（≥10 字，富文本）；**优先级**（如 `中`）；可选分类/附件 | 逐项校验；描述不足 10 字会提示 |
| 8 | 点击 **「创建工单」** | 成功提示；跳转/可在工单列表看到新单，编号形如 `TKT-202610-000173` |

> 实测（2026-10-05）：客户 B2CCUST 手工建类型后成功创建工单 **#220（TKT-202610-000173）**。

## 4. 验证

**界面**
- `/tickets` 列表：新工单在列表中（编号、标题、状态、优先级）。
- 打开详情：标题/描述/类型/优先级与提交一致。

**接口**

```js
// 客户管理员会话：类型列表
fetch('/api/v1/ticket-types', { credentials:'include' })
  .then(r => r.json()).then(d => console.log(d.data.map(t => [t.code, t.name])));

// 工单列表（含新建单）
fetch('/api/v1/tickets?page=1&pageSize=5', { credentials:'include' })
  .then(r => r.json()).then(d => console.log(d.data.items.map(t => [t.ticketNumber, t.title, t.status])));
```

**数据库（可选）**

```sql
SELECT id, ticket_number, title, status, priority
FROM tickets
WHERE tenant_id = (SELECT id FROM tenants WHERE code='B2CCUST02')
ORDER BY id DESC LIMIT 5;
```

## 5. 边界与反例

| 反例 | 操作 | 预期 |
|---|---|---|
| 未建类型就建单 | 直接进 `/tickets/create` 选类型 | 选择器为空、无法提交（这正是模板缺口的表现，不是缺陷崩溃） |
| 标题过短 | 仅 1 个字符 | 前端校验拒绝（≥2 字） |
| 描述过短 | 少于 10 字 | 前端校验拒绝（≥10 字） |
| 跨租户越权 | 服务商未分配此客户仍试图读该单 | 403 `MSP_ALLOCATION_REQUIRED`（见 [08](./08-audit-and-isolation-verification.md)） |

## 6. 排错

| 现象 | 处置 |
|---|---|
| `/tickets/types` 打开 403 | 当前账号无 `ticket_type` 权限；用客户首管执行 |
| 保存类型报预设相关权限错误 | 用「新建类型」而非「从预设安装」；或给角色加 `install_preset` 权限 |
| 建单提交 400/403 | 检查是否选到无权限分类/工作流；查看 Network 响应里的 message |
