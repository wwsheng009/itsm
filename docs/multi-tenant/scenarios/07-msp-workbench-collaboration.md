# 场景 07 · 服务商工作台：跨客户协作（回复 / 改状态 / 指派 / 批量）

> **状态**：当前（2026-10-05 实测）｜**定位**：服务商员工**不切换会话**地在多个客户间处理工单
> **读者**：服务商管理员/技术员、测试
> **前置**：[场景 05](./05-msp-allocation-management.md) 已把当前员工分配到目标客户；客户侧已有工单（[场景 06](./06-customer-ticket-type-and-ticket.md)）

---

## 1. 场景目标与验收判据

| 判据 | 通过标准 |
|---|---|
| 跨客户可见 | 工作台列表出现**多个客户**的工单（按当前用户有效分配收敛）；客户列清晰 |
| 视图过滤 | 顶栏客户过滤器可切换「全部 / 子集」，URL 同步、刷新可复现 |
| 行内操作 | 回复/改状态/指派可用；**每个按钮严格按该条 `allowedActions[]` 渲染** |
| 客户可见 | 客户侧刷新后能看到服务商回复（评论）与状态变化 |
| 审计留痕 | 每次操作产生条目级审计（`workbench.action` 类事件） |
| 批量安全 | 批量操作先给「客户分布确认」，逐条结果可查（成功/失败分开） |

## 2. 操作步骤（浏览器）

### 2.1 进入工作台与过滤

| 步骤 | 操作 | 预期界面反馈 |
|---|---|---|
| 1 | 服务商员工登录 → 左侧 **跨客户工作台**（`/msp/workbench`） | 页面加载工单列表；顶栏有**客户过滤器**（全部客户 / 多选客户，带计数徽标） |
| 2 | 点击顶栏过滤器，勾选某个客户（如 `B2CCUST02`） | 列表收窄为该客户；URL query 出现 `customerTenantIds=<id>`（工作台页内同步） |
| 3 | 浏览器刷新 / 复制 URL 新开标签 | 过滤状态复现（可分享） |
| 4 | 切回「全部客户」 | 列表恢复跨客户视图；说明文案提示"顶栏客户过滤器只改视图不改会话；行内操作按客户授权实时判定" |

> **授权口径**：工作台数据按**当前用户的有效分配**收敛；未分配客户既看不到数据，也无法通过头/路径/请求体访问（4 通道 403，见 [08](./08-audit-and-isolation-verification.md)）。

### 2.2 行内操作（单条）

| 步骤 | 操作 | 预期界面反馈 |
|---|---|---|
| 5 | 目标工单行点 **「回复」** | 弹窗「回复工单 TKT-…」；文本域提示"输入回复内容（将写入该客户工单评论并按条目审计）" |
| 6 | 输入回复内容 → 提交 | 提示「回复已发送」；客户侧随后可见该回复 |
| 7 | 点 **「改状态」** → 选择新状态（如 `处理中`）→ 提交 | 提示成功；列表状态徽标更新；客户详情同步 |
| 8 | 点 **「指派」** → 确认（弹窗文案："将工单指派给**当前 MSP 技术员（你）**"） | 提示「已指派给当前技术员」；列表"处理人"列显示当前用户 |
| 9 | （观察）未授权按钮 | 按钮置灰/提示"当前不可回复 / 当前不可改状态 / 当前不可指派"，原因来自服务端 `allowedActions[].reasonText` |

> 实测（2026-10-05）：对客户工单 **#220** 完成「回复（客户可见）→ 改状态=处理中」；客户侧详情同步可见。

### 2.3 批量操作（跨客户护栏）

| 步骤 | 操作 | 预期界面反馈 |
|---|---|---|
| 10 | 勾选多条工单（可跨客户） | 底部/顶部出现批量工具条：**批量回复 / 批量改状态 / 批量指派** |
| 11 | 点「批量回复」 | 弹窗先展示**客户分布确认**（各客户命中条数）；文本域提示"批量回复将写入 N 条工单（逐条审计）" |
| 12 | 提交 | 弹出**逐条结果**（成功/失败分列，含失败原因）；成功的在客户侧可见 |
| 13 | 「批量指派」 | 提示"批量指派将把所有选中工单指派给当前登录的 MSP 技术员（服务端按提交人记录 managed_by）"，确认后执行 |

## 3. 验证

**界面（服务商侧）**：列表客户列/状态/处理人变化与操作一致；批量后结果抽屉逐条可查。

**界面（客户侧）**：客户账号打开该工单详情 → 评论区出现服务商回复；状态与工作台一致。

**接口**

```js
// 服务商：工作台列表（可带客户过滤）
fetch('/api/v1/msp/workbench/tickets?limit=10', { credentials:'include' })
  .then(r => r.json()).then(d => console.log(d.data.items.map(t =>
    [t.ticketNumber, t.customerTenantId, t.status,
     t.allowedActions?.map(a => a.action + ':' + a.allowed).join(',')])));

// 单条回复
fetch('/api/v1/msp/tickets/<工单id>/reply', {
  method:'POST', credentials:'include',
  headers:{ 'Content-Type':'application/json', 'X-Customer-Tenant-ID':'<客户id>' },
  body: JSON.stringify({ content:'受理中，请补充日志' })
}).then(r => r.json());
```

> 具体请求体字段以 Network 面板实际载荷为准；本页描述的是**界面路径**，接口示例用于独立复核。

**审计**：打开 `/msp/audit`（[场景 08](./08-audit-and-isolation-verification.md)），在动作分布/明细中可见本次操作。

## 4. 边界与反例

| 反例 | 操作 | 预期 |
|---|---|---|
| 未分配客户 | 手工在 URL/请求头塞入未分配客户 id | 服务器 403 `MSP_ALLOCATION_REQUIRED`；界面不显示该客户数据 |
| 客户被暂停 | 对 `status=suspended` 客户操作 | 条目只读态（`CUSTOMER_INACTIVE`），不渲染操作按钮 |
| 越权动作 | 某状态/角色不允许回复 | 按钮禁用并给出原因；绕过界面直接调接口仍被服务端拒绝 |
| 批量混合状态 | 批量改状态含不可操作条目 | 逐条结果中失败条目给原因，成功条目正常生效 |

## 5. 排错

| 现象 | 处置 |
|---|---|
| 工作台为空 | 当前员工无有效分配（先做 [05](./05-msp-allocation-management.md)）；或过滤器选中了无关客户 |
| 按钮全部置灰 | 查看 tooltip 原因；确认客户未暂停、状态允许、具备 `msp_ticket:write` |
| 回复客户侧看不到 | 确认回复提交成功且非"仅内部"语义（当前实现回复写入客户可见评论）；刷新客户页 |
