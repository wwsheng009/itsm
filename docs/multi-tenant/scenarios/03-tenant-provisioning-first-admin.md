# 场景 03 · 租户开通向导（模板供给 → 首个管理员 → 完成）与首登强制改密

> **状态**：当前（2026-10-05 实测；两次开通均跑通）｜**定位**：把空租户变成"可登录、有基础数据"的可用租户
> **读者**：平台管理员、实施交付、测试
> **前置**：[01](./01-platform-create-provider-tenant.md)、[02](./02-platform-create-customer-tenant.md) 的租户已创建；平台管理员登录

---

## 1. 场景目标与验收判据

| 判据 | 通过标准 |
|---|---|
| 模板就绪 | 开通向导显示 **已就绪**（readiness 各项 required 计数 > 0） |
| 首管可用 | 向导生成/接受首个管理员；用该账号成功登录 |
| 合规登录 | 首次登录被要求**修改密码**，改密后才能进入业务页 |
| 可复查 | 再次打开向导：显示「已存在首个管理员」/已创建态（幂等） |

## 2. 操作步骤（浏览器）

### 2.1 打开向导

| 步骤 | 操作 | 预期界面反馈 |
|---|---|---|
| 1 | 平台账号 → `/admin/tenants` → 目标租户行点击 **「开通」** | 弹出「租户开通 · <名称>」三步向导弹窗：**模板供给 → 首个管理员 → 完成** |
| 2 | 观察第 1 步 | 显示模板版本与 7 项基线清单；未供给时整体标记 **待供给**，缺失项显示「缺失」 |
| 3 | 点击 **「开通模板」** | 按钮进入 loading；成功后清单刷新为计数（如角色/权限/菜单等），整体变为 **已就绪** |

> **超时提示**：本机低配环境一键供给可能超过 120s（前端请求超时）。此时**不要重复狂点**——重新打开向导看 readiness；若仍未就绪，可用 §6 的 CLI 供给后重开向导。

### 2.2 创建首个管理员

| 步骤 | 操作 | 预期界面反馈 |
|---|---|---|
| 4 | 供给就绪后进入第 2 步「首个管理员」；在表单填写 | 字段：**用户名**（占位提示 `admin-<租户编码>`，可自定义）、**邮箱**（可选）、**密码**（留空自动生成 12–128 位） |
| 5 | 点击 **「创建管理员」** | 显示「首个管理员已创建」；若为自动生成口令，出现**一次性密码区块** |
| 6 | 点击 **「复制」** 保存口令 | 按钮变「已复制」；**关闭弹窗后无法再次查看** |
| 7 | 进入第 3 步「完成」 | 显示「租户 <名称> 开通流程已完成」与登录提示；可关闭 |

> 实测（2026-10-05）：MSPB2C / B2CCUST 两个租户均完成供给，并各自生成一次性口令；首管登录均触发强制改密。

### 2.3 首管首次登录（强制改密）

| 步骤 | 操作 | 预期界面反馈 |
|---|---|---|
| 8 | 打开 `/login`，用新首管账号+一次性口令登录 | 登录成功后**不进入业务页**，跳转强制改密页 |
| 9 | 输入新密码并确认提交 | 提示修改成功，进入业务首页；之后用新密码登录 |

> 服务商首管登录后落 **provider 家**（自己租户）；客户首管落客户租户。未认证页不暴露任何租户信息（隐私口径）。

## 3. 验证

**界面**
- 再次打开同一租户的「开通」：第 1 步已就绪、第 2 步显示「该租户已存在首个管理员」（幂等）。
- 首管登录后：服务商首管可见 `MSP` 相关菜单（工作台/分配管理/审计看板）；客户首管可见客户业务菜单。

**接口**

```js
// 平台账号：readiness（7 项基线 + 首管数量）
fetch('/api/v1/tenants/<租户id>/readiness', { credentials:'include' })
  .then(r => r.json()).then(d => console.log(d.data));
// 预期：items 各项计数 > 0；ready=true；bootstrapAdmins=1（创建首管后）

// 幂等复跑（可选）：provision 接口可重复调用
fetch('/api/v1/tenants/<租户id>/provision', { method:'POST', credentials:'include' })
  .then(r => r.json()).then(d => console.log(d.data));
```

**数据库（可选）**

```sql
SELECT count(*) AS admins FROM users
WHERE tenant_id = (SELECT id FROM tenants WHERE code='B2CCUST02') AND status='active';
```

## 4. 边界与反例

| 反例 | 操作 | 预期 |
|---|---|---|
| 首管重复创建 | 再次提交「创建管理员」 | 后端 409 / envelope 4090；界面降级提示「该租户已存在首个管理员」，不产生第二个账号 |
| 弱口令 | 自定义密码低于策略 | 提交报错并内联提示（服务端按目标租户密码策略校验） |
| 未改密直接访问业务 | 用一次性口令登录后直接改 URL 到业务页 | 仍被强制改密守卫拦截，跳回改密页 |

## 5. 角色差异（后续会用到）

| 租户类型 | 首管身份（开通后） | 说明 |
|---|---|---|
| `msp_provider` | `role=admin` + `msp_role=provider_admin` + 租户内 `msp_admin` 角色 + home membership | 可进 MSP 管理面；数据面按分配 |
| `msp_customer` / `saas_customer` | `role=admin` + 客户侧角色（如 `customer_user`）+ 角色边 | 进客户业务页 |
| 平台根 `default` | `super_admin` | 平台级；生产首管须走 bootstrap 流程 |

> 历史缺陷提示（已修复，2026-10-05）：修复前首管恒为 `super_admin` 且 `msp_role` 空，导致"服务商管理员能读全量租户目录/进不了 MSP 页面"。若你的环境出现这两种现象，说明版本过旧。

## 6. 供给超时/失败时的 CLI 兜底（运维视角）

```powershell
cd E:\projects\itsm\itsm-backend
# 方式一：仓库内命令（按本机实际命令名为准，见 docs/usage/…… 或 make help）
go run ./cmd/provision_tenant -h
# 方式二：用构建产物（scripts/msp/build-provision-tenant.sh 生成）
# 供给时指定 tenant id 或 code，执行后回向导复查 readiness
```

> 供给是**幂等**的：重复执行不会重复插入基础数据；执行后向导应显示"已就绪"。
