# 场景 04 · 建号（平台通道 / MSP 通道 / 租户通道 + 邀请扩展）

> **状态**：当前（2026-10-05 实测：平台通道 + MSP 通道跑通；租户通道与邀请为扩展章节）｜**定位**：为服务商与客户创建账号
> **读者**：平台管理员、服务商管理员、客户方管理员、测试
> **前置**：[场景 03](./03-tenant-provisioning-first-admin.md) 完成（租户已开通、首管可登录）

## 1. 通道总览（谁给谁建号）

| 通道 | 入口（浏览器） | 建号者 | 目标租户 | 实测状态 |
|---|---|---|---|---|
| A 平台通道 | `/admin/tenants` 行内 **「建号」** | 平台管理员 | 任意租户（含服务商租户） | ✅ 2026-10-05 |
| B MSP 通道 | `/msp/management` → **「为客户建号」** | 服务商管理员 | 其名下客户租户（服务端二次校验分配） | ✅ 2026-10-05 |
| C 租户通道 | `/admin/users` → **「新建用户」** | 租户内管理员 | 本租户 | 扩展（按 §5 执行） |
| D 邀请通道 | `/admin/users` → **「邀请用户」** | 租户内管理员 | 本租户（邀请受理） | 扩展（按 §6 执行） |

> 前置开关：后端需 `USER_PROVISIONING_CHANNELS_ENABLED=true`（见 [00 §2](./00-environment-and-accounts.md)），否则跨租户通道不可用。

## 2. 通道 A · 平台建号（含服务商员工 MSP 角色）

| 步骤 | 操作 | 预期界面反馈 |
|---|---|---|
| 1 | 平台账号 → `/admin/tenants` → 目标租户行点 **「建号」** | 弹出建号表单 |
| 2 | 填写：**用户名**（3–50 位）、**姓名**、**邮箱**（格式校验）、**初始密码**（≥6 位，按目标租户密码策略） | 逐项校验 |
| 3 | 若目标是**服务商租户**：**「MSP 角色」必填**，选择 `provider_admin` 或 `provider_agent` | 下拉出现且必填；客户租户不显示该字段 |
| 4 | 提交 | 成功提示；账号出现在该租户用户列表；可在目标租户登录 |

> 实测：为 MSPB2C 创建 `b2c_tech`（`provider_agent`），登录成功。

## 3. 通道 B · MSP 为客户建号

| 步骤 | 操作 | 预期界面反馈 |
|---|---|---|
| 1 | 服务商管理员登录 → **分配管理**（`/msp/management`）→ 右上 **「为客户建号」** | 弹出建号表单，且带 **「客户」** 下拉（列出本服务商客户） |
| 2 | 选择目标客户；填写 用户名/姓名/邮箱/初始密码 | 同通道 A 校验 |
| 3 | 提交 | 账号创建在客户租户；服务端按分配做二次授权校验（越权拒绝） |

**反例（建议验证）**：用 `provider_agent`（未分配该客户）尝试为某客户建号 → 服务端拒绝（403/业务错误），界面内联报错。

## 4. 验证（通道 A/B 通用）

**界面**：目标租户的用户列表出现新账号；服务商员工在**服务商租户**用户列表中可见且带 MSP 角色。

**接口**

```js
// 服务商管理员：确认员工与 MSP 角色（示例走 MSP 客户目录语境）
fetch('/api/v1/users?page=1&pageSize=10', { credentials:'include' })
  .then(r => r.json()).then(d => console.log(d.data.items.map(u => ({u:u.username, msp:u.mspRole}))));
```

**数据库（可选）**

```sql
SELECT u.id, u.username, u.role, u.msp_role, u.tenant_id
FROM users u WHERE u.username = 'b2c_tech';
```

## 5. 通道 C · 租户内建号（扩展）

1. 客户方管理员（或服务商管理员在自己租户）登录 → `/admin/users`；
2. 点击 **「新建用户」**，填写：用户名/姓名/邮箱/初始密码/角色（以界面实际字段为准）；
3. 保存后在列表看到账号，并可用该账号登录本租户。

> 验证：新账号登录落本租户；访问本租户业务页。

## 6. 通道 D · 邀请受理（扩展）

1. 租户管理员 → `/admin/users` → **「邀请用户」**：在弹窗中创建邀请（邮箱、角色等）、查看列表/状态过滤、可**撤销**、可**复制邀请链接**；
2. 把链接发给受邀人：落地页 `/invite/<token>`（无需登录，页面回显租户/脱敏邮箱，不暴露多余信息）；
3. 受邀人设置密码并提交 → 按邀请角色入租户 → 登录。

> 关联设计：`plan/msp-user-interaction-flows.md`（UF-02 邀请流程）；邀请链接为**路径式**，token 单次、有过期时间。
> 实测边界：服务端对过期/已用 token 返回明确错误；刷新落地页不会泄露租户列表。

## 7. ⚠️ 已知限制（务必先读）

1. **建号通道不写 home membership / RBAC 角色边**（实施方案 v1.69 登记，待后续批次修复）：通道 A/B/C 新建的**普通员工**账号会出现"能登录、但菜单为空/路由守卫 403"的现象；MSP 员工若已被分配客户，**MSP 数据面接口仍可用**（分配即授权）。
   **本阶段规避**：
   - 演示 MSP 工作台请使用**服务商首管**（`provider_admin`，自带 `msp_admin` 角色）或为其建号后由授权流程补角色；
   - 需要普通员工完整菜单时，先在目标租户用首管账号于**角色管理**里给该员工绑定角色（本目录不展开，属 RBAC 既有能力）。
2. **服务商租户建号必须带 MSP 角色**：否则 `isMSP=false`，MSP 页面与接口全部不可达。
