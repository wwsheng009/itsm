# 238 展示优化证据：工作台计数口径与文案收口（2026-10-13 第五轮）

> 版本：`1.8.0-dev.39d6c0b6`（demo 8089）｜提交：`39d6c0b6`

## 1. 报障与核查结论

- 报障：`demo.msp.manager` 顶栏客户徽标显示 8/8/7，切换客户后"显示 2 个工单"，疑似不一致。
- 核查（两个数据源 + DB 对账）：

| 来源 | 接口 | 口径 | 实测（华辰/仁和/云帆） |
|---|---|---|---|
| 顶栏客户徽标 / SLA 看板 / 用量看板 | `GET /msp/workbench/summary` | `open`＝**未关闭**（∉ resolved/closed/cancelled；30s 缓存） | 8 / 8 / 7 |
| 工作台列表 | `GET /msp/workbench/tickets?customerTenantIds=X` | **全部状态**、limit 50；`total`＝本页条数 | 12 / 12 / 11 |

- DB 对账（全部/未关闭）：mfg 12/8、med 12/8、edu 11/7 —— **两源与库完全一致，无数据错误**；
  唯一问题是**文案与展示口径**：徽标"待处理"实为"未关闭"（含挂起/处理中），列表含终态且无口径说明，
  与 SLA 看板"超期 2"等数字并排时极易被读成同一指标不一致。

## 2. 优化（`39d6c0b6`）

| 变更 | 内容 |
|---|---|
| CustomerFilter 文案 | 徽标"待处理"→**"未关闭"**；"超SLA"→"超期"；tooltip/脚注明确"未解决/未关闭/未取消，含挂起与处理中" |
| 工作台「当前范围摘要」 | 列表页新增同源摘要卡：**未关闭/超期/临近/未指派** + 说明"下方列表含全部状态"；新增 `useWorkbenchSummary`（react-query，30s stale 与后端 TTL 对齐），刷新按钮联动 refetch |
| 测试 | CustomerFilter 文案断言更新；相关两套件 22 例全绿；tsc/eslint 全绿 |

## 3. 部署与线上复验（`1.8.0-dev.39d6c0b6`，仅前端重建 + backend/ai retag）

- 顶栏 popover：`未关闭 8 / 超期 2`（华辰、仁和）、`未关闭 7 / 超期 2`（云帆）+ 口径脚注；无"获取失败"。
- 选中华辰（`?customerTenantIds=3`）：摘要卡 **未关闭 8 / 超期 2 / 临近 3 / 未指派 0**（与徽标同源同数），按钮"1 个客户 8"，列表 12 行，卡内注明"下方列表含全部状态"。

## 4. 备注

- "2"的可能来源（均为不同指标，非统计错误）：SLA 看板行"超期 2"；状态筛选"挂起"2 条（华辰）；MSP 托管单 2 张；
  深切"进入客户"后目标租户内的行级可见面按该租户权限计算（跨租户面 ≠ 租户内面，canon I2）。
- 遗留小隐患：列表接口 `total`＝本页条数；若要展示"共 N 条"需服务端补全量计数（本次未改动接口契约）。
