# MSP 登录与作用域切换细化方案（隐私优先）

> 状态：**Draft v0.1（待评审）**｜日期：2026-09-29｜范围：登录页隐私约束、账号类型分派、域名/企业代码定位、服务商登录后切换器、错误码与防枚举、与既有方案的修订点
> 关联：[目标架构方案](./msp-target-architecture.md)（§3/§4/§9）｜[用户交互流程图](./msp-user-interaction-flows.md)（F-04/F-05、§0.5）｜[主方案](./msp-user-lifecycle-and-tenant-switching-plan.md)（§5.3）｜[作用域模型分析](./msp-scope-model-analysis-and-ai-gateway-reference.md)（§1.7/§2）
> 决策来源：2026-09-29 产品约束——**登录页不得出现多租户选择器**（泄露客户隐私）。

---

## 0. 摘要（TL;DR）

**核心约束（P-0，隐私）**：**登录页/未认证接口不得暴露"该账号可访问哪些租户"**——登录页不出现租户选择器、不列出任何租户；多客户信息只在**认证之后**（应用内顶栏）出现。

**目标行为（按 `account_kind` 分派）**：

| `account_kind` | 登录页输入 | 登录后落地 | 切换器 |
|---|---|---|---|
| `customer` | 邮箱/用户名 + 密码（可选：专属域名或**企业代码**文本输入） | **唯一租户**（账号绑定），直接进入 | ❌ 无（永不出现） |
| `provider` | 邮箱/用户名 + 密码 | **provider 作用域（家）** | ✅ 顶栏切换器（provider + 已分配客户） |
| `platform` | 邮箱/用户名 + 密码 | 平台控制台（治理模式） | ✅ 治理用租户选择器（管理台内，认证后） |

**关键修订**：原设计"服务方登录命中多作用域 → `409 SCOPE_SELECTION_REQUIRED` + 登录页一次性选择"**作废**（隐私原因）；改为"登录落 provider 家 → 应用内切换"。分析文档"可借鉴 ⑧（登录多候选 409 + 候选列表）"**不采纳**，改为登录后切换。

## 1. 隐私原则与威胁模型

### 1.1 为什么登录页不能有租户选择器

| 威胁 | 说明 |
|---|---|
| **客户关系泄露** | 登录页若列出"你所属/可访问的租户"，任何拿到账号密码前的人（或撞库成功者）即可看到该服务商服务了哪些客户——这是服务商最敏感的商业信息 |
| **租户枚举** | 选择器/接口可被用来枚举客户租户（名称、编码、是否存在） |
| **账号归属泄露** | "该账号属于租户 X"的报错/响应可被用来判断某人是否在目标公司任职（社工面） |

### 1.2 隐私红线（必须遵守）

1. **未认证面零租户信息**：登录页 DOM、登录/注册/找回密码接口的响应与错误，不得包含租户名称、编码、列表、数量；不得因"账号可访问多个租户"而改变响应结构；
2. **失败原因统一**：账号不存在 / 密码错误 / 租户不匹配 / 域名不属于账号 → **同一错误码与文案**（服务端内部记录真实原因并审计）；
3. **域名入口不泄露归属**：不存在的租户域名 → 通用页（不提示"该租户不存在/已停用"）；
4. **认证后才展示**：租户列表/切换器仅出现在已认证的应用内（顶栏），且仅 `provider`/`platform` 可见；
5. **审计内部可追溯**：所有真实失败原因、目标租户、来源域名写入审计与安全日志（仅供平台侧）。

## 2. 目标行为：按账号类型分派

### 2.1 客户账号（`account_kind=customer`）

- **单租户强约束**（DB 级，见目标架构 §3.2 `uq_customer_single_scope`）：登录后**只能**进入其唯一租户；
- **无需选择**：服务端按账号解析唯一租户；前端不渲染任何切换控件；
- **域名/企业代码**：用于**定位与校验**（专属入口），不是选择器（§3）：
  - 命中其唯一租户 → 正常登录；
  - 与唯一租户不一致 → 统一 401（内部审计 `tenant_mismatch`）；
- **数据异常兜底**：若出现多个 active 作用域（理论上被 DB 约束禁止）→ 拒绝登录 + 告警（fail-closed），绝不自动选。

### 2.2 服务商账号（`account_kind=provider`）

- **登录落地 = provider 作用域（家）**：不因"上次看过哪个客户"而在登录时进入客户上下文（避免"登录即进入某客户"的误解与审计歧义；`last_active` 仅用于切换器排序/高亮，见 §4.4）；
- **顶栏切换器**（登录后可见，§4）：provider 家 + 已分配客户列表；
- **登录页无任何客户信息**：即使该服务商分配了 20 个客户，登录页也只有一个普通表单。

### 2.3 平台账号（`account_kind=platform`）

- 登录落地 = 平台控制台；治理模式的租户选择器**在控制台内**（认证后），高危操作二次确认 + 审计（目标架构 §5.2/§4.2）。

## 3. 域名 / 企业代码定位（不是选择器）

### 3.1 优先级与形态

| 形态 | 示例 | 说明 |
|---|---|---|
| **专属子域名**（首选） | `acme.itsm.example.com` | 后端按 `Host` 解析租户（复用 `middleware/tenant.go` 的子域解析）；前端展示客户品牌；无需用户输入 |
| **路径/参数**（链接直达） | `/login?tenant=ACME` | 用于邀请/通知邮件直达；参数只做定位，不展示候选 |
| **企业代码文本输入**（兜底） | 登录表单折叠项"企业代码（由管理员提供）" | 仅无子域部署时启用；**纯文本输入，不联想、不枚举、不校验存在性提示** |
| 无（默认） | 共享登录页 | 服务端按账号解析（客户→唯一租户；服务商→provider） |

### 3.2 校验规则

1. **客户账号**：目标租户（域名/代码/参数解析所得）必须等于账号唯一租户，否则统一失败；
2. **服务商/平台账号**：**域名不改变落地**——一律落各自入口；若通过客户专属域名登录，提示"请使用服务商入口"（不暴露该域名对应客户信息）；
3. **域名/代码不存在或已停用**：通用页/统一失败（不区分原因）；
4. **账号唯一性**：保持 `username/email` **全局唯一**（主方案 Q3），与域名/代码无关——域名只用于定位租户，不参与账号唯一性判定。

### 3.3 防枚举细节

| 项 | 要求 |
|---|---|
| 响应一致性 | 无论账号是否存在、租户是否匹配，响应体结构/时延特征尽量一致（恒定文案；必要时恒定耗时） |
| 速率限制 | 按 IP + 账号双维度失败计数与退避；域名枚举尝试计入安全指标 |
| 审计 | 内部记录 `attempted_tenant`、`source(domain/code/none)`、`result`、`reason`；不对外回显 |
| 前端 | 登录失败只显示通用文案；不根据错误码分支展示"租户不存在/无权"等差异化提示 |

## 4. 服务商登录后切换器（应用内）

### 4.1 位置与可见性

- **位置**：应用顶栏（全局布局），与用户菜单并列；
- **可见性**：仅 `provider`/`platform` 且作用域数 > 1；`customer` 永不渲染；
- **指示**：当前作用域常驻显示（如"当前客户：Acme（只读）"/"服务商工作台"），避免在错误客户下操作。

### 4.2 数据来源与接口

| 接口 | 用途 | 约束 |
|---|---|---|
| `GET /api/v1/auth/tenants` | 切换器数据源（修正语义：home ∪ 有效分配 ∪ 平台全量） | **仅认证后可用**；不返回无权限租户；不暴露其他服务商客户 |
| `POST /api/v1/auth/switch-tenant` | 切换（重签 JWT + 撤销旧 refresh + 审计） | 目标必须命中有效作用域；失败不泄露原因差异 |
| 切换响应 | 目标租户上下文 + 该作用域的角色/权限 | 前端据此刷新菜单/权限/缓存（目标架构 §9） |

### 4.3 交互

```text
顶栏 [作用域切换器 ▾]
  ├─ 服务商工作台（provider 家）
  ├─ ──────────────
  ├─ Acme 科技        （msp_manager）
  ├─ Beta 制造        （msp_tech）
  └─ …（多客户时提供搜索/最近使用）
选中客户 → 切换 → 顶栏指示更新 → 当前页若不属于目标作用域则回到目标作用域首页
```

- 切换后：菜单/权限/数据缓存**全部按新作用域重算**；进行中的请求取消；未保存表单给出确认；
- 切换失败：保持原作用域，明确提示（不静默回退）。

### 4.4 `last_active` 的定位（修订）

- **不再**作为登录落地（登录落 provider 家）；
- 仅用于：切换器排序（最近使用置顶/高亮）、P1 可选的"记住上次作用域"用户偏好（即使开启，也只是**登录后自动切换一次**，登录页仍无选择器）；
- 采用前必须 `CanAccessTenant` 复核（作用域可能已被回收）。

## 5. 与既有方案的修订点（差异清单）

| # | 既有设计 | 修订后 | 落点 |
|---|---|---|---|
| R1 | 服务方登录多作用域 → `409 SCOPE_SELECTION_REQUIRED` + 登录页一次性选择 | **作废**；登录落 provider 家，应用内切换 | 目标架构 §4.2/§4.3/§9；流程图 F-04/§0.5 |
| R2 | 登录响应 `availableTenants[]` 候选列表 | **移除**；候选列表移到认证后的 `/auth/tenants` | 主方案 §5.3.2 |
| R3 | 分析文档"可借鉴 ⑧ 登录多候选 409 + 候选列表" | **不采纳**（隐私覆盖）；⑧ 修订为"登录后切换" | 分析文档 §0.4 |
| R4 | 客户方"多命中 → `SESSION_AMBIGUOUS`" | 保持（但属 DB 约束下的数据异常，非交互路径） | 目标架构 §4.3 |
| R5 | `last_active_tenant_id` 作为登录落地依据 | 降级为"切换器排序 + 可选偏好"；登录落地固定 provider 家 | 本文件 §4.4 |
| R6 | 登录页可选租户字段（`tenantCode`） | 保留为**定位手段**（子域/链接参数/折叠文本输入），明确"非选择器、不枚举" | 本文件 §3 |

## 6. 分期与验收

| 批次 | 内容 |
|---|---|
| P0 | 登录页移除任何租户列表/选择器；`409 SCOPE_SELECTION_REQUIRED` 下线；统一失败响应；`/auth/tenants` 语义修正 + 认证后使用；顶栏切换器（服务商/平台） |
| P1 | 专属子域名入口（Host 解析 + 品牌）；折叠"企业代码"输入；"记住上次作用域"偏好；切换器搜索/最近使用 |
| P2 | SSO 场景的域名入口扩展；审计看板（域名枚举/失败原因分布） |

**验收（安全）**：

- A1 登录页/登录接口在"账号可访问 N 个租户"时不返回任何租户信息（抓包断言：无租户名称/编码/列表字段）；
- A2 客户账号带错误域名/代码 → 与"账号不存在"返回**同一**错误码与文案；
- A3 服务商账号通过客户域名登录 → 不进入客户上下文、不泄露该域名归属；
- A4 切换器仅认证后出现，`customer` 账号 DOM 中无切换器节点；
- A5 切换后菜单/权限/数据按目标作用域重算（对照目标架构 §9 验收）。
