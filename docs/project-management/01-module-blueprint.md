## 1. 定位与边界

### 1.1 一句话定位

项目管理模块管理**有明确起止的一次性交付工作**：立项 → 计划 → 执行 → 验收 → 结项复盘。它与 ITSM 管理的"持续性服务过程"（工单/事件/问题/变更/SLA）互补，并通过单据关联、流程绑定、CMDB 关系把两者缝在一起。

### 1.2 三类项目来源

| 类型 | 说明 | 阶段 |
|---|---|---|
| IT 内部项目 | 系统上线、机房搬迁、安全整改、网络改造等 | **P0 支持** |
| 服务改进项目（CSI） | 由问题/复盘孵化，结项沉淀知识库与 Known Error | **P1 支持** |
| MSP 客户交付项目 | 服务商为托管客户实施交付 | **P2 后置**（见 [05 MSP 交付](./05-msp-delivery.md)） |

### 1.3 边界（做什么 / 不做什么）

**做**：项目主数据与状态机、WBS 任务、里程碑、成员与角色、风险/问题台账、交付物、单据关联、进度汇总、结项复盘。

**不做（本阶段明确排除，最佳实践裁决见 [07](./07-completeness-review.md)）**：
- Jira 式无限 issue type 体系、Sprint/Scrum 专有模型；
- 跨租户数据引用（项目不引用他租户任何记录）；
- 需求/范围管理实体（默认）：范围说明 + 交付物清单（KB/附件）承载，需求入口走服务请求；出现"逐条评审/变更跟踪/逐条验收"场景再单独立项；
- 挣值管理（EVM）与财务级核算；
- 资源自动均衡/冲突强制消解（只做只读负荷热图）；
- 会议管理实体（纪要走知识库/附件）；
- 独立 Program/项目集实体（组合=报表聚合视图）；
- 外部人员独立主数据（见 [04 身份与成员](./04-membership-and-external-users.md)，用 membership 派生标签）。

## 2. 现状盘点（2026-10 基线）

| 能力 | 现状 | 差距 |
|---|---|---|
| 项目主数据 | 极简字段 + 租户内 code 唯一 | 缺状态机、类型、父子、健康度、进度、实际日期 |
| 项目成员 | `user_tenant_membership_org.org_type=project` 可挂人 | 缺项目角色（PM/成员/干系人）语义 |
| 任务/WBS | 无 | 需新增 `ProjectTask` |
| 里程碑 | 无 | 需新增 |
| 单据关联 | 无（ticket 无 `project_id`） | 需单据侧字段 + 项目工作台聚合 |
| 流程/审批 | BPMN 绑定 + `project_manager` 审批人解析器已有 | 需注册 `business_type=project` |
| CMDB | Project↔Application↔Microservice 边已有 | 项目↔CI 直接关联、影响分析纳入项目上下文 |
| 前端 | 列表 + 弹窗 CRUD；"进度"列无 API | 需工作台/详情/看板 |

## 3. 能力矩阵（P0 / P1 / P2）

### P0 —— 单租户闭环（1~2 个迭代）

| 能力 | 说明 |
|---|---|
| 项目主数据升级 | 状态机 `planning → active → suspended → completed → cancelled`（关键流转走专用端点 + 乐观锁 + 409 语义）；类型、父子项目、健康度、自动进度汇总 |
| 项目编号 | 沿用 `code`（租户内唯一 + 校验）；可选自动编号（PRJ-xxxx，对齐 `ticket_number`/`change_number` 先例） |
| 项目成员 | `project_member`（user_id + 项目角色 PM/成员/干系人）；候选来自目标租户活跃 membership |
| 项目任务 | `ProjectTask`：WBS 树、负责人、状态、计划/实际时间、进度、工时估算 |
| 单据关联 | ticket/incident/problem/change/service_request 增加可空 `project_id`；项目详情聚合展示 |
| 项目工作台 | 详情页：概览 / 任务 / 关联单据 / 成员 / 附件 / 动态 |
| 可见性 | datascope 行级守卫：非成员不可见（管理角色除外） |
| 前端改写 | 去掉占位"进度"列，接入真实数据；项目详情路由 |

### P1 —— 计划与交付治理

| 能力 | 说明 |
|---|---|
| 项目模板 | 从模板一键生成阶段/里程碑/任务/检查单（幂等）；对标工单类型 preset 与流程模板分发模式 |
| 阶段门 | 立项/计划评审/验收/结项四道门，走 `process_binding.business_type=project` + 审批链 + 门禁规则（见本节末「阶段门」表） |
| 计划基线 | 计划批准时冻结不可变快照（任务计划日期/里程碑/预算），实时展示计划 vs 实际偏差；不做 EVM |
| 里程碑 | `project_milestone` + 到期通知（复用 notification + outbox） |
| 任务依赖 | `project_task_dependencies`：**v1 仅 FS**；SS/FF 与关键路径后置；甘特为可选视图 |
| 流程绑定 | 立项/结项审批复用 BPMN + 审批链（`project_manager` 解析器现成） |
| 结项清单 | 任务清零/单据关闭或转出/资产与许可登记（链接 asset/license/vendor/contract）/复盘 KB/成员回收（含 provider 投影回收） |
| 结项门禁 | 未关闭的关联变更/事件阻止结项；结项自动生成复盘 KB 草稿 |
| 结项满意度 | 触发 CSAT 调研（复用 `survey`/`survey_response`） |
| 搜索与待办 | 项目/任务纳入全局搜索；"我的项目任务"聚合进个人工作台 |
| 团队归口 | 项目归口 team/group（对齐 `membership_org` 既有维度） |
| 状态报告 | 状态报告模板与周期定义（数据驱动，AI 增强后置 P2） |
| CSI 场景 | 问题单 → 项目任务转化；项目风险 → 问题单 |

### P2 —— 经营化与 AI

| 能力 | 说明 |
|---|---|
| 预算/成本 | 轻量预算字段（不做财务级核算） |
| 工时 | 先任务级实际（开始/完成时间 + `actual_hours`）；worklog/timesheet 视需要再评估 |
| 资源负荷 | 只读热力图（按周：任务估算/剩余 vs 工作日容量）；不做自动均衡/冲突强制 |
| 风险/问题台账 | `project_risk`（kind=risk/issue），支持转问题单/变更 |
| 采购/资产登记 | 结项清单中登记资产/许可（链接既有 `asset`/`asset_license`/`vendor`/`contract`）；不做采购流程——**PE-26 已落地**：`project_asset_links`（同租户弱引用 + 软删 + 未删行唯一）+ 4 端点（列表/新增/删除/候选选择器），结项清单返回 `assetsLinks` 明细；门禁语义不变（确认/豁免），详见 [plan/p2-procurement-design.md](./plan/p2-procurement-design.md) |
| 报表与度量 | 组合视图、按时交付率、里程碑达成率、阶段门一次通过率、资源利用率（复用 reports/dashboard） |
| AI | 项目周报/状态摘要生成、风险预警、会议纪要转任务（走 LLM Gateway，保留审计与降级路径）——**PE-25 已落地**：`/projects/:id/ai/{summary,risk-warnings,minutes/tasks}`，AI 不可用一律 200 降级（摘要→事实派生、预警→规则信号），纪要只出建议不落库；详见 [plan/p2-ai-design.md](./plan/p2-ai-design.md) |
| MSP 交付 | 见 [05 MSP 交付](./05-msp-delivery.md)，P2 起评估 |

### 阶段门（stage-gate，P1 核心机制）

| 门 | 时点 | 门禁规则 | 载体 |
|---|---|---|---|
| 立项门 | `planning → active` 前 | 经理任命 + 类型/预算（可选）+ 干系人登记 | BPMN 审批 + 审批链 |
| 计划门 | 进入执行前 | 任务/里程碑齐备 + **基线冻结** | 校验 + 流程任务 |
| 验收门 | 交付完成前 | 检查单全过 + 交付物签收 | 里程碑状态 + 附件 |
| 结项门 | `→ completed` 前 | 任务清零、关联单据终态、结项门通过、复盘草稿/资产登记/成员回收齐备（**CSAT 不阻塞**，见 D-20）；结项自动生成复盘 KB 草稿 | 门禁服务 + 审计 |

## 4. 与 ITIL 模块的关系

| 模块 | 关系 |
|---|---|
| 工单/事件 | 服务过程记录；可挂项目；项目任务可生成工单/事件 |
| 问题 | 项目风险的升级出口；CSI 项目的输入源 |
| 变更 | 项目交付的变更载体；项目工作台聚合"进行中的变更" |
| 服务请求/开通 | 交付类项目的执行项可纳入项目进度 |
| CMDB | 项目↔应用↔微服务↔CI；变更影响分析可带项目上下文 |
| SLA | 项目任务/里程碑可绑定交付 SLA（内部用 `sla_definition`；MSP 用合同绑定） |
| 知识库 | 交付物、复盘、模板沉淀为 KB 文章 |
| BPMN | 立项/结项/预算审批的流程载体 |
| 通知 | 任务分派、里程碑到期、状态变更 |
| 审计 | 立项/结项/成员变更/预算调整全量留痕 |

## 5. 命名约定（消歧）

本仓已有三类"任务"，UI 与 API 命名必须区分：

| 实体 | 归属 | 前端文案建议 |
|---|---|---|
| `ProcessTask` | BPMN 流程任务 | 流程任务 / 待办（流程） |
| `ProvisioningTask` | 服务请求开通任务 | 开通任务 |
| `ProjectTask`（新） | 项目管理 | 项目任务 |

API 路径统一 `/api/v1/project-tasks`（避免裸 `/tasks`）；权限码前缀 `project:`（P0 复用 `project:read/write`，P1 视需要拆 `project:task:write`）。
