## 三、仍未修复项

### B1 输入静默改写 — ❌ 未修复
- **复现**：项目工作台 → 任务页 → 新建任务 → 「估算工时（小时）」输入 `999999999`（控件声明上限 1000000）。
- **结果**：
  1. 输入过程中**无任何超出上限的提示或红框**；
  2. 失焦后数值被**静默改为 `1000000`**，无 toast、无字段提示；
  3. 保存后任务表显示 `1000000 / -`；
  4. 更严重的是该钳制值**直接进入项目汇总**——项目概览工时显示 `1000009 / 0 小时`（模板任务 9h + 被钳制的 1000000h），一个明显不合理的工时数字被当作有效数据参与项目级统计。
- **影响**：用户既不知道输入被改写、也不知道上限在哪；而汇总层又把越界值当作事实数据使用，会让项目工时指标失真。
- **建议**：超限时在字段下方即时提示「最大 1,000,000 小时，超出部分将被截断」，或在输入阶段直接阻止超限字符；同时考虑为工时设置更贴近业务的合理上限（如 10000 小时）并对异常值做汇总层校验。

## 五、本轮新发现的次要问题

1. **列表页表格横向溢出（B5 残留）**
   项目列表与模板列表的列数已增长到 10 列以上，首屏只能看到「项目名称 / 项目编号 / 类型 / 状态 / 健康度 / 进度」，「归口团队」「所属部门」「操作」全部需要横向滚动才能看到；操作按钮内的「工作台」「编辑」文字仍逐字换行为竖排（如"工\n作\n台"）。而任务表已经做了操作列固定，列表页未同步处理。
   **建议**：列表页操作列同样做 sticky 右固定，操作按钮设 `white-space: nowrap`，或把「所属部门/归口团队」等次要列折叠进"更多"。

2. **阶段门表格「门禁阻塞项」列被压至 0 宽**
   上一轮该列表头是竖排挤压，本轮变为列头完全不可见（DOM 中存在 `门禁阻塞项` 列，但渲染宽度为 0）。虽然该项目该列数据全为 `-`，但列头消失会让用户不知道这一列存在。
   **建议**：为该列设最小宽度（如 120px），或数据全空时合并显示"无阻塞项"。

3. **工时越界值污染汇总**
   被钳制的 1000000 小时直接计入项目估算工时合计（1000009 小时），说明汇总层缺少异常值校验。**建议与 B1 一并处理**。

## 六、修复质量评价

**本轮的进步**
- **A2 是本轮最完整的修复**：不是只补展示，而是补齐了默认映射、手工覆盖、报表聚合三层，并主动声明归口的语义边界（不影响可见性、用于报表分组与通知候选），这种"说清副作用"的做法值得保留。

**仍需收口**
- **B1 是唯一实质未修复项，且危害被放大**：静默钳制 + 计入汇总，等于把一个错误的工时数字当作项目事实。建议列为下一轮 P0。
