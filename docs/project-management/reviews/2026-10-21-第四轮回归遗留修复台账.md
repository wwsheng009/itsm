## 2. B1 · 工时静默钳制（第四轮：文案在说谎）→ 根因重做

### 第四轮实测

- 页面提示「0 ~ 10,000 小时；**超出会被拒绝保存（不会静默截断）**」；
- 输入 `999999999` → 无红框、无提示；
- 点确定 → **任务创建成功**，工时显示 `10000`。

即：**文案承诺拒绝，实际静默截断后保存**。

### 真正的根因（前两轮都没找到）

```tsx
<InputNumber min={0} max={TASK_HOURS_MAX} />   // ← 问题在这一行
<Form.Item rules={[validator]}>                 // ← 校验器永远看不到越界值
```

antd `InputNumber` 的处理顺序是：

1. `onBlur` 时按 `max` **先把值钳制**到 10000；
2. 再把钳制后的值同步给 Form；
3. 此时 `validator` 收到的 `value` 已经是 `10000` → **校验必然通过**。

所以只要传了 `max`，无论校验器写得多严格都不会触发。前两轮分别改了"提示"和"校验器"，但都没去掉 `max`，因此两轮都无效。

### 本次修复

| 层 | 变更 |
|---|---|
| **前端（根因）** | 工时输入**移除 `max`**（只保留 `min={0}`），antd 不再改写用户输入；`validateTrigger={['onChange','onBlur']}` 让越界即时红字 |
| 前端（文案） | 改为 `0 ~ 10,000 小时；超出将阻止保存并提示`——与实现一致，不再承诺做不到的事 |
| 前端（模板） | 模板任务工时同样移除 `max` 并补 validator（此前只靠 `max` 钳制，等于没有校验） |
| 后端 | 沿用 `MaxTaskHours=10000` 400 拒绝（第三轮已实现） |
| 汇总 | 沿用第三轮的越界排除 + `invalidHoursTasks` 告警 |

### 验证（新增回归守卫）

`src/pages/(main)/projects/__tests__/task-hours-limit.test.ts`（7 用例）：

- 校验函数：`999999999` / `10001` → 拒绝；`10000` / `0` / 空 / 小数 → 通过；负数/NaN → 拒绝；
- **源码断言**：`detail.tsx` 与 `templates.tsx` 的工时 `InputNumber` **不得出现 `max=`**（防止后人"顺手加回上限"再次让校验失效）；
- 两处 `TASK_HOURS_MAX = 10000` 口径同源。

> 用源码断言而非渲染测试：该缺陷的本质是「组件属性 + 校验时机」的组合，快照无法表达"不要传 max"。

## 3. 列表页操作列 · 浮层遮挡 8 列 → 根因修复

### 根因（全局 CSS，非页面代码）

`src/styles/globals.css`：

```css
.ant-table { overflow: visible; }   /* ← 破坏了 sticky 定位上下文 */
```

`fixed: 'right'` 依赖滚动容器裁剪。`overflow: visible` 让 `.ant-table-cell-fix-right` 失去 sticky 定位上下文，退化为**不透明浮层覆盖中间列**。

这解释了为什么"同一套 sticky 在任务表能用、在列表页变成遮挡"——任务表容器结构不同，恰好没被这条规则命中。

### 修复

| 层 | 变更 |
|---|---|
| 全局 CSS | `.ant-table { overflow: hidden }`（圆角由内层 `.ant-table-container` 承担） |
| 列表页 | 列精简：`所属部门 / 归口团队 / 计划结束 / 预算` 4 列合并为「归属与计划」1 列（两行展示），列数 **12 → 9**；`scroll.x` 1600 → 1440 |
| 列表页 | 操作列保留 `fixed:'right'` + `nowrap` |

> 合并后第二行仍完整展示归口 / 计划结束 / 预算，信息不丢失；首屏可同时看到状态、健康度、进度与操作。

## 4. 阶段门「门禁阻塞项」列宽 0 → 补 onHeaderCell

**根因**：`onCell` 只作用于**数据单元格**，表头单元格仍被 `table-layout: fixed` 压到 0 宽。

**修复**：

```tsx
width: 360,
onHeaderCell: () => ({ style: { minWidth: 260, width: 360, whiteSpace: 'nowrap' } }),
onCell:       () => ({ style: { minWidth: 260, whiteSpace: 'normal' } }),
```

同时把 `scroll.x` 从 1360 调为 **1090**（= 各列声明宽度之和 220+100+240+360+170），避免固定布局在剩余空间不足时继续挤压。

## 7. 为什么前三轮反复失效（复盘）

| 轮次 | 做法 | 为什么没用 |
|---|---|---|
| 第一轮 | 加 `onChange` 判断 `value > max` 弹提示 | onChange 拿到的是钳制后的值，条件恒 false |
| 第三轮 | 改 `Form.Item` validator + 保留 `max` | validator 在钳制**之后**执行，永远看到合法值 |
| **第四轮** | **移除 `max`**，只留 validator | 钳制不再发生，校验器能看到真实输入 |

**教训**：当组件库自带"输入修正"行为时，任何依赖"原始输入"的校验都必须先关掉修正，否则校验逻辑是死代码。
本轮已用源码断言锁死"工时控件不得出现 `max=`"，防止回退。
