## 2. A2 · 归口字段无法维护（P0）→ 本次修复

### 根因（源码核验）

1. **前端无维护入口**：`Project` 类型有 `ownerTeamId`，后端 `POST/PUT /projects` 也接受该字段并做同租户/未软删/active 校验（`ensureOwnerTeam`），但列表/详情**没有任何选择器** → 用户无法设置。
2. **报表取数漏列**（本轮新发现）：`ListProjectsForReportGroups` 的 `Select(...)` 未包含 `department_id`，导致部门维度恒为 0，报表分组只能落到「未归口」。

### 修复

| 层 | 变更 |
|---|---|
| 后端 | 新增 `GET /api/v1/projects/owner-team-candidates`（租户级字典，`project:read`；只返回同租户、未软删、`status=active` 的团队；`q` 匹配名称/代码，`limit ≤ 50`；最小字段 `{id,name,code}`） |
| 后端 | `TeamRef` 增 `Code`；新增 `Repository.ListActiveTeamRefs` |
| 后端 | 报表分组改为按 `(ownerTeamId, departmentId)` 聚合，输出 `departmentId/departmentName` |
| 后端 | **修复 `ListProjectsForReportGroups` 漏选 `department_id`**（真实缺陷） |
| 前端 | 新建/编辑项目弹窗新增「归口团队」下拉（可留空；空态提示先到组织管理创建团队） |
| 前端 | 报表中心新增「所属部门」列；行 key 改为 `team+dept` 组合（避免重复 key） |

### 验证

- `TestOwnerTeamCandidates`：只返回 active 未删同租户团队；inactive/软删/跨租户均被排除；关键词过滤生效。
- `TestOwnerTeamCandidatesEndpoint`：端点信封与最小字段。
- `TestReportGroupsIncludeDepartment`：两个部门 + 无部门 = 3 组，计数 2/1/1 合计 4，部门名称正确。

> 说明：存量项目仍显示「未归口」是**数据事实**（历史上从未写入过 `owner_team_id`），系统无法推断归口；
> 现在用户可在编辑弹窗补录，补录后报表分组会立即反映。

### 构建阻断（已修复，值得记录）

首次构建 `1.8.0-dev.cb6142f1` **失败**：

```
Could not resolve "../Sidebar.module.css" from "src/components/layout/sidebar/MenuItems.tsx"
```

`cb6142f1` 删除了重复的 `components/layout/Sidebar.module.css`，但 `MenuItems.tsx` 仍以 `../` 引用它。
本地 `tsc --noEmit` **不解析 CSS**，因此未暴露；生产 `vite build` 会解析 CSS import，直接失败。
`b3f9762c` 将引用改为同目录 `./Sidebar.module.css` 后构建通过。

> 教训：删改 CSS/资源文件时，本地校验必须包含 `npm run build`（或至少 `vite build`），
> 仅 `tsc --noEmit` 不足以保证可构建。
