## 二、严重问题（A 类）逐项结论

### A1 必填校验 — ✅ 已修复
- **复现**：新建项目弹窗仅填「项目名称」，直接点「确定」。
- **结果**：弹窗不再关闭，项目经理、所属部门、计划起止三项同时出现红框与错误提示；逐项补齐后错误提示实时消失，才允许提交。
- **评价**：校验时机（提交时拦截 + 修正后即时消除）符合主流表单预期，避免了上一轮"空数据直接落库"的问题。

### A2 所属部门 / 归口落库 — ⚠️ 部分修复
- **已修复部分**：项目列表新增「所属部门」列，新建项目正确显示「信息技术部」；进入编辑弹窗，所属部门正确回填为「信息技术部」，可正常修改。
- **未修复部分**：
  - 编辑弹窗中**不存在"归口"可维护字段**，用户无处设置归口。
  - 列表中「归口」列对我的项目仍显示「未设置」，其他项目同样。
  - **报表中心**按归口分组仍为「未归口 6」，新增项目也未归入任何归口分组。
- **判断**：修复停留在"所属部门"这一展示层字段，归口的数据映射（部门→归口）与报表聚合逻辑未接入。这是一个**功能未完成**而非样式问题。

### A3 结项清单首屏实时计算 — ✅ 已修复
- **复现**：分别进入新项目（仅模板数据）与已结项项目的结项清单。
- **结果**：页签直接显示 `(2/6)`、`(1/6)`，无需先点"刷新"；正文警示条「存在 4 项结项阻塞」「存在 5 项结项阻塞」与下方明细逐条吻合（通过项 + 阻塞项 = 6）。
- **评价**：计数、警示语、明细三者同源，上一轮"首屏显示 0/6、点击后才变成真实值"的问题已消除。

### A4 阶段门审批方式透明化 — ✅ 已修复
- **结果**：阶段门表格新增「审批方式」列，明确区分：
  - `人工审批`（附流程实例编号）
  - `自动放行（未配置流程）`（附 `auto_approved_no_flow` 标记）
- 页面顶部同时给出说明：「计划门、验收门未配置审批流程，提交后将自动放行（不计入一次通过率）」，并声明自动放行是降级行为、不等同于审批通过。
- **评价**：这是本轮最关键的"诚实性"修复。上一轮把自动放行显示为"已通过"，会让管理者误判治理强度；现在把"未配置流程"这一治理缺口直接暴露出来。

### A5 计划门冻结基线 — ✅ 已修复
- **结果**：计划门说明明确写出「无基线时自动冻结 v1，已有基线不重复」。
- **评价**：从"自动冻结但不告知"变为"声明冻结规则"，用户可预期冻结结果。

### A6 时间源偏移 — ✅ 已修复
- **复现**：2026-10-21 当日新建两个项目。
- **结果**：编号分别为 `PRJ-20261021-2153`、`PRJ-20261021-3114`，日期段与当天一致。
- **评价**：上一轮固定偏移一天（编号为 PRJ-20261020-xxxx），现已与服务器当天日期同步。

### A7 健康度算法区分度 — ✅ 已修复
- **结果**：健康度改为按数据完备度分层：
  - 有完整任务/里程碑数据的已结项项目 → `健康`
  - 已结项但无任务/里程碑数据 → `健康（数据不足）`
  - 进行中且无填报数据 → `关注（数据不足）`
- **评价**：上一轮"所有项目一律显示健康"的失真已解决，且用括号标注置信度，而不是编造一个精确结论。

### A8 阻塞数口径一致 + 结项按钮禁用 — ✅ 已修复
- **结果**：
  - 结项清单警示条阻塞数与明细条数完全一致（4 项、5 项两例均核对通过）。
  - 非阻塞项（如 CSAT 满意度）单独说明，不再混入阻塞计数。
  - 已结项项目页头不再出现「结项」按钮。
- **评价**：口径统一，且按钮状态与项目状态一致，避免重复结项。

## 三、一般问题（B 类）逐项结论

### B1 输入静默改写 — ⚠️ 部分修复
- **复现**：新建任务「估算工时（小时）」输入 `999999999`，控件声明上限 1000000。
- **结果**：输入过程中无任何提示；失焦后数值被静默改为 `1000000`，任务保存后表格显示 `1000000 / -`。
- **问题**：仍属"静默改写"，用户不知道自己的输入被改写、也不知道上限是多少。建议超限时立即在字段下方提示"最大 1,000,000 小时，已按上限取值"。

### B2 数字控件上下限 — ⚠️ 部分修复
- **已修复**：新建项目「预算金额」`valuemin=0 / valuemax=1000000000`（上一轮 max=0，无法输入）；新建任务「估算工时」`valuemax=1000000`，箭头增减正常。
- **残留**：**模板管理 → 任务定义中的「估算工时」控件上限仍为 0**。实测可键入 8 并递增到 9，说明输入未被真正封死，但控件声明 `valuemax=0`，加号按钮上限判断与之矛盾，属于控件配置遗漏，存在不同浏览器/不同输入方式下行为不一致的风险。

### B3 人员 ID 翻译 — ✅ 已修复
- **结果**：成员表格新增「姓名」列，显示「系统管理员」，用户名 `admin` 单独成列。
- **评价**：从"直接暴露内部 ID"变为"姓名 + 账号分离展示"，可读性达标。

### B4 工作台表格列宽 / 操作区遮挡 — ❌ 未修复
- **复现**：模板链路验证项目 → 任务页。
- **结果**：
  - 任务表 9 列（任务名称/状态/优先级/负责人/计划/进度/工时/工单/操作）横向溢出，**「操作」列在首屏完全不可见**，必须拖动底部横向滚动条才能点到"开始""更多"。
  - 阶段门表格「门禁阻塞项」表头文字仍被压成竖排（每行一个字）。
- **评价**：这是本轮唯一完全未修复的问题，且直接影响主流程可用性——任务页是使用频率最高的页面，每次操作都要先横向滚动。建议：操作列固定右侧（sticky）、次要列（工单/工时）默认收起、表头设置最小宽度。

### B5 列表页表格列宽 / 中文竖排 — ✅ 已修复（列表页）
- **结果**：项目列表表格列宽合理，中文正常横排，无逐字换行。
- **备注**：工作台内表格的竖排问题未同步修复，已计入 B4。

### B6 添加成员弹窗遮挡 — ✅ 已修复
- **结果**：添加成员弹窗改为纵向分区（候选成员 → 同步设为项目经理 → 项目角色），各区域不再互相覆盖，无需再靠坐标试探点击。

### B7 模板链路打通 — ✅ 已修复（重点验证）
- **复现**：模板管理 → 新建模板（名称 + 里程碑"验收通过，偏移 5 天" + 任务"启动/环境部署，估算 9h"）→ 状态切「已激活（可应用）」→ 保存 → 新建项目时选择该模板。
- **结果**：
  - 模板列表新增「定义（阶段/任务/检查项/里程碑）」列，显示 `1 阶段 / 1 任务 / 0 检查项 / 1 里程碑`。
  - 模板状态有「草稿（不可应用）」与「已激活（可应用）」区分，新建项目下拉仅列出已激活模板，并提示「创建后自动生成计划」。
  - 创建成功提示「项目已创建并应用模板（阶段 1 / 任务 1 / 检查项 0 / 里程碑 1）」。
  - 进入项目工作台复核：任务页确有 2 条任务（含模板定义的"启动""环境部署"，估算 9h），里程碑 1 条，概览显示"已应用模板"。
- **评价**：上一轮"模板只能创建、无法应用"的断链已彻底打通，且定义了 阶段→任务 分组、里程碑偏移天数 两条关键规则，模板具备了实用价值。

### B8 风险责任人必填 — ✅ 已修复
- **复现**：新建风险/问题，仅填标题，不选负责人，点保存。
- **结果**：保存被拦截，字段下方红字提示「请选择负责人（须为项目活跃成员）」。
- **评价**：不仅加了必填，还明确了约束范围（须为活跃成员），避免了选到已离场人员。

### B9 必填标记统一 — ✅ 已修复
- **结果**：风险弹窗中「标题」「负责人」均为红色星号 + `required` 属性；「概率」「影响」明确标注「可选」。
- **评价**：必填与可选的视觉区分统一，不再出现"有的必填有星号、有的没有"的混乱。

### B10 口径一致 — ✅ 已修复
- **结果**：概览页工时汇总同时给出估算与实际，并附统计口径说明「实际已填报 0/2 任务」（另一项目为 0/1）。
- **评价**：解释了"0 小时"到底是"没人填"还是"填了 0"，消除了指标歧义。

### B11 文本截断 — ✅ 已修复
- **复现**：新建任务，名称填入 75 字符（含中文 + 英文字母数字）。
- **结果**：保存成功后在任务表中完整换行显示为三行，未被截断、未溢出到相邻列、未遮挡状态与优先级。
- **评价**：从"截断丢字"改为"自动换行完整呈现"，长名称可读性达标。

### B12 指标失真 — ✅ 已修复
- **结果**：状态报告明确输出「数据缺口：未冻结计划基线（无预算/计划偏差可判）」，健康度标注 `yellow（数据不足，结论仅供参考）`；归口团队无数据时显示 `-` 而非编造值。
- **评价**：与本轮 A7 同一设计思路——缺数据时标注"数据不足/不可判"，而不是给出一个看似精确的结论。这是本轮最值得保留的改进原则。

### B13 浮层键盘可达 — ⚠️ 部分修复
- **已修复**：下拉浮层可用键盘完成选择（聚焦后 `↓` + `Enter` 生效），实测在「模板选择」「模板状态」「项目经理」「所属部门」四处均成功。
- **残留**：下拉选项在无障碍树中被判为离屏元素，缺少可寻址的 `option` 节点，逐个选项的读屏播报与点击定位仍不可靠；纯读屏用户难以感知选项列表内容。
- **评价**：键盘可用性已达到"能操作"，但可访问性仍停留在"能猜"。建议为浮层选项补齐 `role="option"` 与稳定的可寻址结构。

## 四、修复质量评价

**做得好的地方**
1. **从"给结论"转向"给依据"**：A4 审批方式、A7 健康度置信度、B10 工时口径、B12 数据缺口，四处都选择了暴露真实状态而非美化展示，这是治理类系统最需要的诚实性。
2. **模板链路是完整的端到端修复**：不只是加了字段，而是打通了"定义 → 激活 → 可选 → 落库生成"全链路，并在创建后提示生成结果，可验证。
3. **校验类修复到位**：A1、B8、B9 三处都做到了"提交拦截 + 错误定位 + 修正后即时消除"，且明确了约束条件（须为活跃成员）。

**建议优先处理**
| 优先级 | 问题 | 建议 |
| --- | --- | --- |
| P0 | B4 任务表操作列不可见 | 操作列 sticky 固定右侧；工单/工时等次要列默认收起 |
| P0 | A2 归口字段无法维护 | 补充归口字段（或建立部门→归口映射），并同步报表中心分组 |
| P1 | B1 工时静默钳制 | 超限即时提示上限值，说明"已按上限取值" |
| P1 | B2 模板任务工时上限=0 | 统一模板任务与实例任务的控件上下限配置 |
| P2 | B13 选项无障碍 | 补齐 option 角色与可寻址节点 |
| P2 | 工作台表头竖排 | 表头设最小宽度，禁止逐字换行 |
