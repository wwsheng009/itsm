## 三、功能性缺陷（影响数据 / 流程正确性）

### A1 · 必填校验完全失效 🔴 P0

**实测表现**

- 新建项目时项目经理、所属部门字段带 `*` 必填标记。
- 仅填写项目名称即提交，提示「保存成功」，项目创建成功。
- 生成的项目在列表中显示：负责人「-」、归口「-」、计划结束「-」、预算「-」。

**影响**

产生无归属、无计划、无预算的空壳项目；后续健康度、资源负荷、报表统计均缺失归属主体。

**建议**

前后端双层硬校验；对历史空壳数据提供清洗入口与批量补全。

---

### A2 · 所属部门字段不写入后端 🔴 P0

**实测表现**

- 编辑项目时，所属部门下拉成功选中「信息技术部」，输入框正确回填该值，保存提示「保存成功」。
- 返回列表，「归口」列仍为「-」。
- 报表中心「归口分组（项目数 / 健康度分布）」中，**全部 5 个项目均归入「未归口」**。

**影响**

「归口 / 部门」维度的全部分析链路失效：报表中心归口分组、组合视图「部门」Tab、部门维度健康度分布均无有效数据。此为**系统性数据写入缺陷**，非个例。

**建议**

排查该字段的实体映射与持久化链路（前端回显正常说明前端已拿到值，问题在提交载荷或后端写入）；修复后回归验证报表中心与组合视图。

---

### A3 · 结项清单首屏数据陈旧 🔴 P0

**实测表现**

- 进入「结项清单」Tab 时，「任务清零（阻塞项：无 todo / in_progress / blocked 任务）」显示 **已通过**。
- 但「任务」Tab 中任务「需求调研与方案设计」处于 **进行中** 状态。
- 在页面触发任一其它操作（如「生成复盘草稿」）后清单刷新，该项才纠正为「未通过（1 个未终结任务）」。

**影响**

用户极易误判为「已满足结项条件」而直接点击结项，导致未完成任务被强制结项，项目数据失真。

**建议**

进入 Tab 即实时计算门禁判定；数据未就绪时显示 loading 骨架而非渲染「已通过」。

---

### A4 · 阶段门审批策略不一致且不透明 🔴 P0

**实测表现**

| 阶段门 | 审批方式 | 流程实例 |
|---|---|---|
| 立项门 | 真实人工审批（提交 → 裁决，间隔 8 秒） | #65 |
| 计划门 | 自动放行 `auto_approved_no_flow` | 无 |
| 验收门 | 自动放行 `auto_approved_no_flow` | 无 |
| 结项门 | 真实人工审批 | #66 |

**影响**

四道门中两道靠自动放行，审批管控形同虚设；且用户事前无法从界面识别哪道门需人审、哪道门会自动通过，违背门禁设计初衷。

**建议**

「未配置审批流程」应作为**配置缺失告警**而非等价于「通过」；在门行显式标注审批方式（人工审批 / 自动放行）；提供管理员配置引导入口。

---

### A5 · 计划门「通过时冻结基线」未执行 🟠 P1

**实测表现**

- 计划门描述明确写「通过时冻结基线」。
- 计划门通过后，查看「计划基线」Tab，仍只有 v1（此前手动冻结产生），未生成 v2，也无任何提示。

**影响**

文档与实现不一致；且「计划基线」Tab 的手动冻结与计划门自动冻结两条路径职责重叠，用户无法预期何时会产生新基线。

**建议**

统一冻结触发时机，二者留一；若保留自动冻结，需修正执行逻辑并给出「已冻结基线 v2」的明确反馈。

### A6 · 时间源整体偏移 🔴 P0

**实测表现**

| 位置 | 显示时间 | 实际系统日期 |
|---|---|---|
| 项目编号 | PRJ-**20261020**-9637 | 2026-10-21 |
| 审批提交/裁决 | 2026-10-20 23:31:53 / 23:32:01 | 2026-10-21 |
| 风险更新时间 | 2026-10-20 23:34 | 2026-10-21 |

| 组合视图交付明细-实际结束 | 2026-10-20 | 2026-10-21 |

**影响**

所有时间戳跨天偏移（疑似 UTC 未转本地时区，或服务器时区配置错误）。影响审批时效计算、SLA 计时、审计合规、报告可信度，且项目编号中的日期与实际创建日不符。

**建议**

服务端统一按租户时区输出时间；前端展示层统一格式化；对存量数据评估是否需要校准。

### A7 · 健康度算法失效 🟠 P1

**实测表现**

- 状态报告生成时：里程碑达成率 0%、任务完成 0/1、计划偏差「未冻结基线」，健康度仍判定为 **green（健康）**。
- 组合视图中 5 个项目健康度**全部为「健康」**，包括：规划中 0% 的 demo、规划中 100% 的 E2E 信息项目、规划中 0% 的 PM P2 验收。

**影响**

健康度恒为「健康」，完全失去预警与区分价值；管理者无法通过该指标识别问题项目。

**建议**

算法引入空值与无基线状态（如「数据不足」）；对「规划中 + 100% 进度」类矛盾数据增加一致性校验；设置分级阈值（健康 / 关注 / 风险）并回归验证。

---

### A8 · 阻塞数口径矛盾，结项按钮未禁用 🔴 P0

**实测表现**

- 页头提示徽标显示「结项门待补 **1** 项」。
- 同一页面告警块显示「存在 **4** 项结项阻塞」。
- 在 4 项阻塞状态下，「结项」仍为可点击的主按钮（仅有静态文案「存在未通过项」）。

**影响**

同一时刻两处数字互相矛盾，损害系统可信度；且存在绕过门禁直接结项的风险。

**建议**

统一阻塞数计算来源；阻塞数 > 0 时禁用结项按钮并给出可点击的阻塞项清单。

## 四、交互与操作逻辑问题

### B1 · 输入被静默改写

新建任务时「计划结束」手动输入 `2026-10-31`，关闭日历面板后再展开负责人下拉，值被自动改写为 `2026-10-28`（疑似「开始 + 7 天」联动强制覆盖用户手动输入），全程无任何提示。

**建议**：联动仅作为默认值，用户手输优先；变更时给出明显提示。

---

### B2 · 数字控件上下限配置错误（组件级缺陷）

- 任务「估算工时」：`valuemin=0`、`valuemax=0`，填入 40 仍可保留，但上下箭头增减失效。
- 风险「关联工单 ID」：同样为 `valuemin=0`、`valuemax=0`。

同一组件缺陷在多处复用，属组件级问题，建议全局修复。

---

### B3 · 字段回显为原始 ID

- 工作台概览「项目经理」显示为 `ID:1`。
- 状态报告正文「项目经理ID: 1」直接输出裸 ID。

应为「系统管理员」。建议建立统一的人员字典翻译层，禁止裸 ID 出现在任何展示位。

---

### B4 · 任务操作区过载且被遮挡

- 操作列 7 个文字链接平铺换行：阻塞 / 完成 / 取消 / 编辑 / 依赖 / 生成工单 / 删除。
- 危险操作「删除」与「完成」并列，无分组、无二次确认差异。
- 「阻塞」链接被右下角悬浮 AI 助手按钮部分遮挡（截图中呈现「阻⊕完成」叠字）。
- 「任务 (1)」页签同样被遮挡为「任⊕1)」。

**建议**：主操作按钮 + 「更多」菜单收纳次要操作；删除操作隔离并二次确认；调整 AI 悬浮球位置或为表格增加安全边距。

---

### B5 · 表格列宽失当，中文竖排折行

- 任务名称「需求调研与方案设计」被逐字折成 9 行竖排，表格几乎不可读。
- 项目列表「负责人」「归口」「计划」「预算」列同现竖排（「系统管理员」竖排显示）。
- 模板页「模板名称」「版本」表头竖排。

**建议**：设置列最小宽度、支持自适应与横向滚动；关键列提供 tooltip 或行内展开。

---

### B6 · 添加成员弹窗遮挡与消歧不足

- 候选成员下拉浮层直接遮挡下方「项目角色」选择器，必须先选人才看得到角色。
- 候选列表仅显示姓名，无部门/邮箱等消歧信息，同名场景存在误选风险。
- 项目已有「项目经理」时，新增成员无「是否同步设为项目经理」提示。
- 浮层选项无法节点点击（`kElementOffscreen`），仅能坐标命中。

---

### B7 · 模板链路割裂，核心效率能力实际不可用

- 新建项目表单中**没有**「选择模板」字段，模板只能在创建后到工作台补加。
- 工作台「应用模板」弹窗下拉提示「暂无已激活模板，请先在「项目模板」页激活」，但弹窗内**无跳转入口**。
- 「项目模板」页数据区为「暂无数据」，系统无任何预置模板。
- 模板页空态仅有插画 +「暂无数据」，无「新建模板」引导按钮、无说明文案。
- 「一个项目只能应用一次模板」为不可逆操作，弹窗未做二次确认。

**结论**：模板这一核心效率能力在本系统中实际完全不可用。

### B8 · 风险无责任人

风险「负责人」标注为「可选」；项目仅 1 名成员时留空仍可保存。结果风险无 owner，后续无人推进。

**建议**：改为必填，或允许留空但触发指派提醒与超期升级。

---

### B9 · 必填标记缺失，边界不清

任务弹窗仅「任务名称」必填；「负责人」附注「（须为项目成员）」却未标 `*`；「估算工时」「计划日期」均可全空。用户无法判断哪些字段真正必填。

- 成员回收「已回收 0 人（保留 PM 与干系人）」仍判为「已通过」，且按钮保持主按钮样式可重复点击。
- 页头「结项门待补 1 项」在阻塞数 3→1 变化过程中始终显示 1，疑似静态值。

---

### B11 · 文本截断与图标重叠

- 结项清单资产列按钮显示「确认登记 豁 免」（「豁免」被拆字）。
- 组合视图右上角「报表中心」按钮文字与图标重叠成「报⊕中心」。

### B12 · 指标失真

组合视图「阶段门一次通过率 100%（一次通过 11 / 已通过 11）」：把 `auto_approved_no_flow` 自动放行的门计入「一次通过」，虚高了真实审批效率。

**建议**：自动放行单独统计或从分母中剔除。

---

### B13 · 可访问性：浮层无法键盘操作

所有下拉、日期选择浮层的选项均无法通过节点定位点击（`kElementOffscreen`），只能坐标命中。这意味着键盘导航与读屏软件无法完成选择，无障碍不达标。

**建议**：为浮层补齐 ARIA 角色与焦点管理，保证 Tab / Enter / Esc 可完成选择。

## 五、设计亮点（建议保留）

1. **阶段门实时预检**：进入即预检，阻塞项右侧直接提供「去处理里程碑 →」直达入口；前置门未通过时正确禁用后续门并说明当前状态。
2. **计划基线冻结 + 偏差对比表**：展示基线值 / 当前值 / 变更百分比，清晰可用（如「进行中 → 已完成，+90%」）。
3. **状态报告一键生成 Markdown**：含任务、里程碑、阶段门、基线偏差全维度指标，支持复制 Markdown 与下载 `.md`，并明确标注「实时派生，不落快照」。
4. **风险转换幂等保护**：「转问题 / 转变更」重复转换会被拒绝并回显既有单据，避免重复建单。
5. **破坏性操作有后果说明**：成员回收弹窗明确说明将回收「成员」角色、保留 PM 与干系人、影响「不再可见该项目」，并有取消/执行双按钮。
6. **豁免需必填原因**：资产/许可登记豁免要求填写原因，且原因在列表中完整回显。
7. **状态机收口正确**：结项后「应用模板」按钮与全部操作按钮整体消失，不再暴露无效操作。
8. **组合视图口径透明**：主动披露算法局限（资源利用率按项目口径会重复计容量、v1 按自然日均摊含周末未接工作日历）；交付率分母透明标注「无计划结束日 1（未计入分母）」；四个明细 Tab（交付 1 / 里程碑 3 / 阶段门 11 / 资源 5）可下钻对账。

## 六、优化建议（按优先级）

### P0 — 数据与流程正确性（必须优先修复）

1. 补全前后端必填校验：项目经理、所属部门、计划起止日期作为硬性拦截；对历史空壳数据提供清洗入口。
2. 修复所属部门字段的持久化与「归口」映射，回归验证报表中心归口分组与组合视图部门 Tab。
3. 结项清单改为进入即实时计算；统一页头徽标与告警块的阻塞数来源；阻塞数 > 0 时禁用结项按钮。
4. 统一阶段门审批策略：未配置流程时给出配置引导与显著标识，禁止把「未配置」等同「通过」；自动放行不计入「一次通过率」。
5. 校正时区 / 日期源，服务端统一按租户时区输出；回归校验编号、审批、报告时间戳。
6. 健康度算法引入空值与无基线状态；增加「状态=规划中 + 进度=100%」类一致性校验。

### P1 — 操作逻辑与效率

7. 取消任务日期「开始 + 7」静默覆盖，改为联动默认值 + 变更提示，用户手输优先。
8. 修复数字输入组件的上下限配置（全局组件修复，避免第三处复用）。
9. 建立统一人员字典翻译层，所有人员字段输出姓名，禁止裸 ID 出现在概览与报告中。

## 八、总体评价

**功能完成度**：★★★★☆
主流程完整闭环，12 个核心环节全部可走通，状态机设计合理。

**数据正确性**：★★☆☆☆
所属部门不落库、时间源偏移、必填校验失效、结项数据陈旧，四项叠加导致输出数据不可信。

**用户操作逻辑**：★★★☆☆
阶段门预检、破坏性操作二次确认设计成熟；但输入被静默改写、模板链路割裂、操作区过载削弱体验。

**操作方便性**：★★☆☆☆
表格列宽严重不足导致中文竖排，是本次审查中影响效率最直观的问题；浮层无法键盘操作、AI 悬浮球遮挡操作按钮进一步降低可用性。

**结论**：产品在业务流程建模上具备较好的完整度与设计深度，但工程实现层面的数据写入、校验与时间处理存在系统性缺陷。建议优先修复 6 项 P0 问题后再投入正式使用，否则归口分析、健康度、审批与审计数据均不可作为决策依据。
